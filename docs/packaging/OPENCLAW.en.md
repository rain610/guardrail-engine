# OpenClaw Integration Guide (guardrail-engine)

Install guardrail-engine gates into OpenClaw as "the same bundle form as Claude Code plugin marketplace"; after installation, agent sessions can directly call gate tools (skill + MCP dual channel). This file is an expanded version of RUNBOOK's "Client Integration" section: complete commands, verification, and pitfalls are authoritative here.

## 0. Prerequisites

- Host machine: Windows (local verification environment; macOS / Linux not verified).
- Node: Use the runtime bundled with OpenClaw desktop (hereafter `<node.exe>`, replace with your installation path).
- OpenClaw entry: `<openclaw.mjs>` (`resources/gateway/openclaw/openclaw.mjs` under desktop installation directory).
- Two critical environment variables only exist in desktop process, default empty in shell, **must be explicitly set first**:

| Variable | Value |
| --- | --- |
| `OPENCLAW_STATE_DIR` | `<OpenClaw state directory>` (e.g., `~/.openclaw`) |
| `OPENCLAW_CONFIG_PATH` | `<OpenClaw state directory>/openclaw.runtime.json` |

## 1. Installation (Main Path: Install via Marketplace)

```powershell
$env:OPENCLAW_STATE_DIR   = '<OpenClaw state directory>'
$env:OPENCLAW_CONFIG_PATH = '<OpenClaw state directory>/openclaw.runtime.json'
$node = '<node.exe>'
$ow   = '<openclaw.mjs>'
$mkt  = '<local marketplace root>\agentguard-tools-marketplace'
& $node $ow plugins install agentguard --marketplace $mkt
```

Marketplace root contains `.claude-plugin/marketplace.json` and `agentguard` bundle (skill + MCP service definition), generated by:

```bash
python integrations/plugins/build_marketplace.py --harness <HARNESS repo root> --out <local marketplace root>\agentguard-tools-marketplace
```

> If using marketplace from "offline installation package": first run
> `python "<package directory>\fix_paths.py" --harness "<your HARNESS path>"` to adapt package config to local machine
> (package contains absolute paths stamped by packaging machine; building marketplace from repo doesn't need this step).

Fallback path (direct bundle install): Copy bundle directory to `<OpenClaw state directory>\extensions\agentguard` then restart desktop.

## 2. Verification

```powershell
& $node $ow plugins list
```

- Expected: `agentguard` appears in extension directory `<OpenClaw state directory>\extensions\agentguard`, status enabled / loaded.
- In agent session test two probes: `harness_doctor` returns rc=0; `harness_list_gates` returns all 4 gates
  (of which 2 enabled by default: example gate and engine self-check; ESLint / Semgrep adapter gates disabled by default).
  (This line is **shipping documentation**, writes "what you should see", so must be current truth; numbers guarded by
  `tests/docs/test_docs_consistency.py`'s number lock — writing different numbers fails immediately.)

## 3. Common Pitfalls

1. **Environment variable loss**: `OPENCLAW_STATE_DIR` / `OPENCLAW_CONFIG_PATH` not in user-level or machine-level environment variables (injected by desktop process); running install commands directly in shell installs to wrong location or errors — explicitly set first then execute.
2. **Marketplace parameter**: Prefer `--marketplace <marketplace root>`; path with spaces must be quoted (PowerShell uses single quotes).
3. **Not effective after install**: Restart desktop or reopen agent session to load extension; if still having issues check `plugins list` status output first.

## 4. Uninstall / Rollback

- One-click (recommended): `python "<package directory>\uninstall.py" --yes` in installation package — withdraws each local integration (including this section's extension) item by item; dry-run by default, `--yes` to execute.
- Manual (equivalent, most stable): Delete `<OpenClaw state directory>\extensions\agentguard` directory, restart desktop.
- CLI uninstall: Use `plugins` subcommand, exact command name subject to `& $node $ow plugins --help` output.

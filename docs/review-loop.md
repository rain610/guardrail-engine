## 什么时候再送外审（触发条件）

出现以下任一情况时，送一轮外审：

1. **守门类部件变更**：新增/改动 checker、规则集、分发器（`harness/hooks-dir/*`）、
   安装器（`sandbox/install_hooks.sh`）、自检（`checks/harness_self_check.py`）、
   看守（`tests/test_lock_inventory.py` + `lock-inventory.json`）、
   冒烟（`sandbox/mutation_smoke.py`）或门禁核心管道（`harness/run_gate.py`、scope/基准判定、
   config 加载）—— **轻量轮**：只审变更面 + 全量套件 + 冒烟 + 看守三件套。
2. **事故触发**：出现任何"锁没接住 / 静默放过 / 静默减护"类事件（含使用侧反馈）→ 回来专项复审。
3. **平台/介质变化**：CI 平台、Python 基线、EOL/快照法、OS/shell 环境变更 → 送审。
4. **发布节点**：打 tag 或对外分发前跑「三件套自检」（全量套件 + 变异冒烟 + 丢锁看守），
   红灯即停；**红灯原因不明才送外审**。
5. **周期性抽查**：无上述事件时，每季度 / 每约 50 次提交做一次缩水版复核。

**再升频条件**：若发生第 2 类事件，回到"每轮交付送审"，直到再次连续两轮零 P1/P2。

## 这个回路积累的三条硬规矩（都是修出来的）

1. **报警不报平安**：一个坏传感器输出"0 个问题 / 0 个对象"且 rc=0，比报错更危险。
   判据是**行为**（退出码 + 命中行 + 无 Traceback），不是关键字。
2. **锁必须跑在真实入口上**：入口若自己会补齐参数（如 `hooks/pre-commit.py` 自己算文件清单），
   就量不到调度器层面的回归 —— 换 `run_gate <gate> --repo <仓> <文件>` 入口，并做**双向对拍**
   （正确态与变异态结果必须不同，否则写上"两态无差异"）。
3. **护盾名单也要有看守**：锁、变异名单、快照清单，任何"名单"被删/改名都会静默减护 ——
   一律"只增不减 + 关键名点名"，并让"变异冒烟"回答"锁还咬不咬"（看守只回答"锁在不在"）。

# agentguard 内部安装包 · v0.1.4-dev（2026-09-18）

> 内部试用版（仅限公司内部使用，请勿外发）。
> 这是**接入体验档**：把「先 clone 引擎仓」从《安装说明》先决条件括号里的一句话，
> 变成随包可执行的一步（`bootstrap.py`），并把"没 clone"与"指错了仓"两种误诊拆开。
> **无破坏性变更**，可直接覆盖安装。

## 包内容
- `agentguard-0.1.4.dev0-py3-none-any.whl` —— CLI + MCP 薄服务（`pip install` 后得到 `agentguard` 命令）
- `marketplace/` —— Claude Code / OpenClaw 插件市场 bundle（技能 + MCP，一次装齐）
- `bootstrap.py` —— **本版新增**：引擎引导（把门禁引擎仓 clone 到本机，接入的第一步）
- `fix_paths.py` —— 换机器路径适配（一条命令改到你的 python / 引擎路径）
- `upgrade.py` —— 升级入口（按你的布局给出该执行的动作，不猜）
- `uninstall.py` —— 一键卸载（默认预演、`--yes` 执行；五项逐项撤回，可逆 + 台账留痕）
- `安装说明.md`（含「零、先 clone 引擎仓」「四、卸载」「五、升级」）/ `OPENCLAW.md` / `LICENSE` / `SHA1SUMS.txt` / `PACK-INFO.json`

## 本版变化（相对 v0.1.3-dev）

### 同事能直接感觉到的
- **拿到包之后的第一步，现在有命令了。** 安装包**不含引擎**是**有意**的（提交钩子 / MCP 注册 /
  编辑期 shim 全都**指向仓库**，引擎一更新你这边就是新的，不用重装包）—— 代价是"先 clone 引擎仓"
  成了你拿到包要做的第一件事，而它此前只写在先决条件的**括号里**。现在：

  ```bash
  python "<本包目录>\bootstrap.py"                     # 默认 clone 到 ~/agentguard
  python "<本包目录>\bootstrap.py" --dir D:/dev/agentguard
  python "<本包目录>\bootstrap.py" --check             # 只体检，不动手
  ```

  跑完它会把**后面两步的命令直接打出来**（路径适配 + 生成覆盖层），照着复制即可。
  三条刻意的"不做"：**不覆盖**已存在的目录、**不更新**已有的引擎仓、**没有 `--yes`**
  （动作是纯增量的，不撤回不删东西）。
- **报错不再指错方向。** 以前无论"还没 clone"还是"路径拼错了"，`fix_paths.py` 都只说
  「没找到 `mcp.py`」——于是你会去反复核对拼写，而问题根本不在拼写上。现在两种情形分开：
  目录**根本不存在** → 直接把可复制的 clone 命令给你；目录在、只是没有 `mcp.py` → 那才是指错了仓。
- **《安装说明》新增「零、先 clone 引擎仓」一节**，讲清包内为什么永远装不出引擎，
  并给了「没 clone 会怎样」的对照；末尾有一处与「二」的**第 0 步**的区分（那个管包内占位符，
  这个管包外引擎从哪来）。

### 维护者能感觉到的

- **清掉 5 处写死的「三支工具」计数**：随包工具三支变四支，那些注释/文档一律改为
  **以常量或产物为准**（`SHIPPED_TOOLS` / `TOOLS` / `ENTRIES`）。写死数量的注释必然在
  下一次加工具时烂掉 —— 本版就是"下一次"。

  造"上一次那份包"时用的是**手写文件名单**，加 `bootstrap.py` 时漏了项，于是这条

  一模一样，两者在输出里长得一样。改为从产物派生。
- 出货契约校验（包内工具与仓库**逐字节相同**）的名单同步收 `bootstrap.py`；包内每支顶层 `.py`
  都必须被《安装说明》点名（该锁自动覆盖新增那支）。

## 安装（三步）
1. `python "<本包目录>\bootstrap.py"` —— clone 引擎仓（本版新增的第一步；已 clone 过会直接跳过并说"什么都没做"）
2. `python "<本包目录>\fix_paths.py" --harness "<你的 agentguard 路径>"` —— 路径适配（每次装/升级都要跑）
3. 按 `安装说明.md` 安装（CLI / Claude 插件 / OpenClaw 任选）

## 升级
见 `安装说明.md`「五、升级」—— 路径引用型（`.mcp.json` 指到你 clone 的仓库）**无需处理**，
pull 即可；副本型（按版本目录放的）重跑安装命令，或 `marketplace add <新路径>`。
**已经 clone 过引擎仓的机器不需要跑 `bootstrap.py`**（它会识别出来并明确告诉你"什么都没做"）。

## 卸载（一步）
包内 → `python uninstall.py --harness <你的 agentguard 路径>`（预演）→ 加 `--yes` 执行。
`bootstrap.py` clone 出来的那个仓库**不在**撤回清单里 —— 那是你自己的仓库，去留由你决定。

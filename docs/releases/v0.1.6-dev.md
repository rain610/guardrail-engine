# agentguard 内部安装包 · v0.1.6-dev（2026-09-19）

> 内部试用版（仅限公司内部使用，请勿外发）。
> 这是**知识档**：治的是「**范式里教你的写法，在你自己的仓里根本不存在**」。
> 上一版治的是"同一份代码在两台机器上得到两种结论"，本版治另一半 —— **文档与真代码不一致**。
> 它比上一版那种更隐蔽：门禁不会报错、屏幕上全是 ✓，**照着抄的人才会写错**。
> 本版把 13 个 PC 仓全量实测了一遍，清掉一整套**凭空捏造**的组件与 API
> （`eagle-drawer` / `useUnsavedGuard` / `closeForce` / `venue/list.vue` / 「130+ 全局组件」），
> 并把三份端级模板都指着的**全局守则接进了安装流程**（此前照《安装说明》做完，它根本不存在）。
> **无破坏性变更**，可直接覆盖安装；各人那份 `local.yaml` 不用改。

## 包内容
- `agentguard-0.1.6.dev0-py3-none-any.whl` —— CLI + MCP 薄服务（`pip install` 后得到 `agentguard` 命令）
- `marketplace/` —— Claude Code / OpenClaw 插件市场 bundle（技能 + MCP，一次装齐）
- `bootstrap.py` —— 引擎引导（把门禁引擎仓 clone 到本机，接入的第一步）
- `fix_paths.py` —— 换机器路径适配（一条命令改到你的 python / 引擎路径）
- `upgrade.py` —— 升级入口（按你的布局给出该执行的动作，不猜）
- `uninstall.py` —— 一键卸载（默认预演、`--yes` 执行；逐项撤回，可逆 + 台账留痕）
- `安装说明.md`（含「零、先 clone 引擎仓」「四、卸载」「五、升级」）/ `OPENCLAW.md` / `LICENSE` / `SHA1SUMS.txt` / `PACK-INFO.json`

## 本版变化（相对 v0.1.5-dev）

### 同事能直接感觉到的

- **PC 范式里那套抽屉写法，是照着 `eagle-model` 的样子编出来的 —— 13 个 PC 仓一个都没有。**
  实测（2026-09-19，13 个 PC 仓 = 11 个受管 gate + 基线仓等）：`<eagle-drawer>` 标签命中 **0 处**，
  `src/components/` 无此文件、`registerGlobComp.ts` 无此注册；`useUnsavedGuard` / `closeForce` /
  `isFullScreen`、`src/composables/`、`venue/` 同样 **0 命中**。而同期 `<el-drawer>`（Element Plus 原生）
  每仓实有 **81~346** 处 —— 抽屉本来就直接用原生组件。
  现在 `pc_page_patterns.md` §6.3 改写为 `el-drawer` 并指向 `pc_vue_form_drawer.md` §二；
  「未保存提醒」改成真有的那个 `closeConfim`（**只弹框问一句，不检测内容改动** —— 原文档把它写成了
  一个自动检测改动的守卫，那是编的）；属性表换成本仓实测的属性频次表；ref 方法换成真身
  `getModelHeight` / `judgeIsFullScreen`；出处从 `venue/list.vue` 换成 `accidentReport/tabs/list.vue`。

- **「130+ 个全局注册组件」也是编的 —— 真数 86。**
  口径：`registerGlobComp.ts` 里**未注释**的 `app.component("eagle-*")`。⚠ 单引号与双引号两种写法都要数
  —— 只按单引号数会把 gxgk / ntrx / 712_v3 数成 0~1。基线仓（手册面向的那个）**86**；
  712_v3 / gxgk / ntrx = 86、ZhongXin / keji = 85、HanBoGaoXin = 82、712 = 67、zhongdj = 66、hy 系三仓 = 57。
  「130+」约等于 `src/components/` 的 `.vue` 文件数（**157** 个，其中 `eagle-*` 123 个）——
  **目录文件数 ≠ 全局注册数**，而原句紧接着就让人去这个文件核对，照着必然对不上。已在原处补口径脚注。

- **`el-drawer` 不再被门禁 warn。** 原 warn 指向一个不存在的封装组件 —— 拿假规则去骚扰真代码，
  只会训练使用者忽略这条 warn，所以整条移除并在原处留注记（写明为什么别再 add 回来）。
  `el-dialog` **保留**，并且这次专门验了它不是同一类错误：`eagle-model` 确有封装
  （`registerGlobComp.ts:72` 注册，各仓 630~988 处），而 `<el-dialog>` 只有 29~41 处。

- **全局守则（`~/.agentguard/GLOBAL_AGENTS.md`）现在真的会被生成。**
  三份端级模板（`golden-patterns/templates/AGENTS_{pc,h5,backend}_slim.md`）都指向它，而它此前
  **没有生成者** —— 只有 `sandbox/bootstrap_agent_env.sh` 会写它，那支脚本不在安装流程里、
  也没有任何调用方。于是照《安装说明》做完，「端级模板指着的那个文件」根本不存在。
  现在由 `install_shim.py`（装编辑期 hook 那一步，**必然会跑到**）顺带渲染。两点要知道：
  **哨兵区**（`<!-- HARNESS:BEGIN ... -->` 到 `<!-- HARNESS:END -->`）内每次重渲染、手改会被覆盖；
  **区外是你自己的，harness 永不触碰**。**卸载时刻意不退它** —— 正因为区外属于你，撤走等于把
  你自己写的规矩一起拿走。只想要守则、不装 hook：`python <HARNESS>/sandbox/global_agents.py <HARNESS>`。

- **新机器上 bootstrap 的三处「屏幕上打着 ✓，实际却没做」已修。** 三处全属这一类：错了不会有人知道。
  ① 薄壳正文写的是 git-bash 形态路径（`/c/Users/...`），而这三个文件正是 **Windows 上的 AI 工具**
  读它的入口路由 —— 实测 Windows Python 打得开 Windows 形态、开 `/c/...` 直接 `FileNotFoundError`。
  改之前它们对任何 Windows 侧工具都是**死指针，屏幕上却一直打 ✓**。
  ② 备份守卫判的是"含不含某串"，而那串在薄壳正文里本来就有 ⇒ **守卫恒假** ⇒ 备份分支永不触发，
  每次都无条件截断重写。真机活证据：那三份 `.bak-20260919` 与现行文件**逐字相同** ——
  它备份的是自己即将覆盖掉的东西，而幸存的那版手写内容一个痕迹都没留下。
  ③ `ln -s` 对**文件**也返回 0 却做一次拷贝，于是 `~/.config/opencode/AGENTS.md` 这种
  "工具会自动加载"的位置上会躺一份**再也不会刷新**的正文副本。这条**专打新机器**
  （只有 dest 不存在时才走这条分支），恰恰是 bootstrap 的主场景。

## 安装（三步）
1. `python "<本包目录>\bootstrap.py"` —— clone 引擎仓（已 clone 过会直接跳过并说"什么都没做"）
2. `python "<本包目录>\fix_paths.py" --harness "<你的 agentguard 路径>"` —— 路径适配（每次装/升级都要跑）
3. 按 `安装说明.md` 安装（CLI / Claude 插件 / OpenClaw 任选）

## 升级
见 `安装说明.md`「五、升级」—— 路径引用型（`.mcp.json` 指到你 clone 的仓库）**无需处理**，pull 即可；
副本型（按版本目录放的）重跑安装命令，或 `marketplace add <新路径>`。
**已经 clone 过引擎仓的机器不需要跑 `bootstrap.py`**。
本版**没有改配置结构**，你那份 `config/harness.local.yaml` 照旧。
⚠ 唯一要额外跑一次的：装了编辑期 hook 的机器，`git pull` 之后跑一遍
`python "<HARNESS>/sandbox/install_shim.py"`，全局守则的哨兵区才会重渲染（见上）。

## 卸载（一步）
包内 → `python uninstall.py --harness <你的 agentguard 路径>`（预演）→ 加 `--yes` 执行。
`bootstrap.py` clone 出来的那个仓库**不在**撤回清单里 —— 那是你自己的仓库，去留由你决定。
全局守则**刻意不退**（理由见上）。

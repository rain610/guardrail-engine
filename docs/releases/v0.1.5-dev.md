# agentguard 内部安装包 · v0.1.5-dev（2026-09-18）

> 内部试用版（仅限公司内部使用，请勿外发）。
> 这是**跨平台档**：治的是「**同一份代码在两台机器上得到两种结论**」。
> 换盘符 / 换用户名 / 在 WSL 上 clone 之后，此前会出现两种症状 —— 一种是**报错但看不懂**
> （每次提交都被拦，说找不到 `python`），另一种更麻烦：**不报错，只是静默什么都不做**
> （33 条仓库路径全部指空，配置看起来却是「配好的」）。
> 本版收尾时又实测出**第三种**，而且是最坏的一种：**报错、看不懂、而且每次都拦**——
> 上一步把路径下沉时顺手连键名一起删了，于是「只配了自己那几个仓」这个**最常见**的形态
> 会让提交链 fail-closed，同时**你自己的代码一个字节都没被检查过**（详见下面第一条）。
> **无破坏性变更**，可直接覆盖安装；各人那份 `local.yaml` 不用改。

## 包内容
- `agentguard-0.1.5.dev0-py3-none-any.whl` —— CLI + MCP 薄服务（`pip install` 后得到 `agentguard` 命令）
- `marketplace/` —— Claude Code / OpenClaw 插件市场 bundle（技能 + MCP，一次装齐）
- `bootstrap.py` —— 引擎引导（把门禁引擎仓 clone 到本机，接入的第一步）
- `fix_paths.py` —— 换机器路径适配（一条命令改到你的 python / 引擎路径）
- `upgrade.py` —— 升级入口（按你的布局给出该执行的动作，不猜）
- `uninstall.py` —— 一键卸载（默认预演、`--yes` 执行；五项逐项撤回，可逆 + 台账留痕）
- `安装说明.md`（含「零、先 clone 引擎仓」「四、卸载」「五、升级」）/ `OPENCLAW.md` / `LICENSE` / `SHA1SUMS.txt` / `PACK-INFO.json`

## 本版变化（相对 v0.1.4-dev）

### 同事能直接感觉到的
- **只配了自己那部分仓库的机器，提交不再被无条件拦住。** 上一版把 33 条路径下沉到你那份
  `config/harness.local.yaml` 时，**顺手把键名一起删了** —— 于是「这个键配置里压根没声明过」与
  「我这台机器没有这个仓」塌成了同一件事。而剩下的那根判据是在**维护机**上调的（那里 33 个键全在），
  所以它只对维护机成立。《安装说明》让你「只写机器上确实存在的那几个仓」，**实测症状**（只填 1 个）：
  自检报 32 行 `❌ 引用未定义的 repo` → 提交钩子把它转成 fail-closed 中断 —— **你每次提交都被拦，
  而你自己的代码一个字节都没被检查过**（拦在自检那一步，根本走不到你的 `.vue`）。同一次输出里
  还自相矛盾：`⚠ … 路径本机不存在 —— 不阻断` 就打在 `❌ … 引用未定义的 repo` 上面，
  说的其实是同一件事。现在键名表回到共享配置（值留空），两根判据各归各位：
  **键名不在表里 = 真配置错**（拼错 / 新 gate 漏登记 —— 任何机器上都拦，那是它唯一会出声的时刻）；
  **键在、你没填 = 本机没这个仓**，常态，不拦，但逐条 `⊘` 列出来、末尾汇总一句，不静默放行。
  你那份 `config/harness.local.yaml` **不用改**：原先怎么填的照旧。
- **换机器不再是「看起来配好了、其实一个仓都没管上」。** 共享配置里原先写着 33 条
  `D:/MyProject/aiauto/agentguard_*` —— 那是**维护机上的事实**，不是团队策略。现在路径一律下沉到
  你自己那份 `config/harness.local.yaml`（gitignored），共享文件只留团队策略那一段。
  新机器上 `run_gate.py --list` 会把「配了但本机不存在」的路径**汇总出一行**（此前逐行打 33 个
  看着都正常的路径，没有一行是真的）。
- **Linux / WSL 上提交不再必然被拦。** 钩子原先调的是裸 `python`，而 Ubuntu 上只有 `python3` ——
  每一次提交都 fail-closed，且报错看不懂。现在 9 个入口都按「**真的能跑起来**」判定
  （`--version` 退出码 0 且输出 `Python 3`），候选顺序 `$HARNESS_PYTHON` → `python3` → `python`
  → `py -3`；一个都找不到时**出声说明原因**再拦，不再让你对着一条看不懂的报错排查拼写。
  （反方向也有洞：Windows 的 `python3` 常是 Microsoft Store 的占位别名，`command -v` 能命中、
  一跑就失败 —— 所以判据落在输出上，不在名字上。）
- **行尾不再按「维护机当年的检出快照」判。** 此前 PC 端的 gate 声明 CRLF、H5 端声明 LF，
  而那是**写这份配置那台机器**的检出形态。后果实测过：拿一个**未曾改动**的 H5 文件去跑都被判
  「行尾异常」（台账 **2026-09-12** 那两行 `gxgk_h5` 全量扫描里 `H5-CRLF` 各记 1489 条，全是误报
  —— 带日期的读数，不是"台账里现在有多少条"）；同事在 WSL 上 clone 之后，PC 端**每个文件**都会被判错。
  现在「期望什么行尾」按**你这台机器这份检出**的事实判定（`.gitattributes` → `core.autocrlf` →
  `ls-files --eol` 的实际多数），判不出来才落端默认 —— 而端默认**逐字节等于今天的行为**，
  所以「判不出来」不是回归。想固定成某个值仍然可以：配置里显式写 `CRLF` / `LF` 即可，语义一字未改。

### 维护者能感觉到的
- **同一份提交在两台机器上打出的包，指纹一致了。** 此前实测逐成员对下来 **8 处**不同
  （5 处行尾、2 处构建机 setuptools 版本、1 处被带跑的派生文件）。本版把这三层分开治：
  **源头**（出货源码按 **git 索引**的口径写，不是工作树的字节）、**出货点**（每个复制点按同一
  口径读）、**判据**（指纹不看平台噪音，但 `SHA1SUMS.txt` 仍是**逐字节**的下载校验清单 ——
  两个哈希各有各的用途，混成一个会在某一天让其中一方说谎）。
- **`harness/_eol_policy.py`（三态解析器，引擎层新增）+ `tests/test_review_v13_batch9.py`（29 例）**。
  判定顺序每一步都有实测支撑，不是推演：`.gitattributes` 最优先（本仓自己就是反例：
  `autocrlf=true` 而 attr 写了 `eol=lf`，先看 autocrlf 会**当场判错**）；否则读 `core.autocrlf`
  （`true`→CRLF / `input`→LF 是 git 的**保证**）；否则仍然走 `ls-files` —— 实测
  `eagle-rmc-mobile-net-hy` 是 `autocrlf=false` 而工作树 **1072 w/crlf / 0 w/lf**，
  「`false` → LF」那条捷径在它身上必错。
- **台账现在记得住「当时的期望行尾凭什么定的」**（`eol_source` / `eol_value` 两个键）。
  这条**零新增 git 调用** —— 来源本来就算出来了，只是被调用的地方丢掉了。**不落键是硬的**：
  不涉及行尾的 gate（后端 / `harness_self`）、被本机关掉的 gate 一律不落这两个键 ——
  每行都挂一个「来源」等于没有来源。半残部署下记 `resolve-failed`，**绝不写 `endpoint-default`**：
  那等于把「没解析出来」和「解析出来正好是端默认」写成同一句话。
- **突变名单 +6（M43–M48）**，且各自单独一条：M43 治的是**编辑动作**而不是代码（gate 键被粘回
  上一行末尾那次真实事故：`--validate` 从 34 个 gate 掉到 13 个而**不报错**，只是「看起来配好了」）；
  M44 断掉「子进程 → 父进程」那条回传通道（实测**单测全绿**，只有端到端读台账那几条红 ——
  这正是那几条锁必须端到端、且不该挂 `_slow` 的硬证据）；M45 把解析失败伪装成端默认。
  M46 把「本机有几条路径」的口径退回「数键在不在」（键名回到共享配置后那个口径**恒为真**，
  正是事故的机制本身）；M47/M48 是同一条判据的两半张脸 —— 一个管提交链最前面的自检、
  一个管 CI 用的 `--validate`，只修一边就是「同事的提交过了而 CI 红」或反过来。
- **`tests/test_repo_key_registry.py`（11 例）**：②③ 两支各起**两次真引擎**（子进程），
  不是单测 `_config` 里的函数 —— ⑤ 跑在子进程里、事故现场就是它，只测函数只能证明「引擎知道
  这个键没填」，证明不了「谁读了它、得出的结论是什么」。同时它反向钉住「键名表不能空」与
  「不许留死键」（声明了却没有 gate 引用的键）。
- **一处同源的复发一并修掉**：`_sanity_check` 里逐 gate 打的「已启用但仓库路径不可用」在
  **零配路径**的机器上是 33 行，正好把上一版专门为它做的汇总又冲掉（钩子 stderr 的 `_compact`
  只有 40 行回灌窗口）—— 同一夹具、同一命令下实测 stderr 非空行 **38 → 5**；
  「只填 1 条」那个形态修复前是 **rc=1 / 32 行 ❌**、修复后 **rc=0**。
  两处前后对照与复量方法见 `reports/_batch7_before_after.txt`。
- **丢锁清单与实测对齐**：48 个模块 = 48 个 `test_*.py`，`total` = 逐模块之和 = 磁盘实测。
  其中 `test_bootstrap.py` 此前**根本没进登记表** —— 按清单自己的注解，未登记的模块
  「删光锁不会被任何检查发现」。
- `tests/test_review_v6.py` 的 doctor 预算 300→600s：**测量修正**，不是性能断言 ——
  实测 doctor 单跑 65~85s，而在全量套件里跑到 370s（成本几乎全在 Windows 进程创建上）。

## 安装（三步）
1. `python "<本包目录>\bootstrap.py"` —— clone 引擎仓（已 clone 过会直接跳过并说"什么都没做"）
2. `python "<本包目录>\fix_paths.py" --harness "<你的 agentguard 路径>"` —— 路径适配（每次装/升级都要跑）
3. 按 `安装说明.md` 安装（CLI / Claude 插件 / OpenClaw 任选）

## 升级
见 `安装说明.md`「五、升级」—— 路径引用型（`.mcp.json` 指到你 clone 的仓库）**无需处理**，
pull 即可；副本型（按版本目录放的）重跑安装命令，或 `marketplace add <新路径>`。
**已经 clone 过引擎仓的机器不需要跑 `bootstrap.py`**（它会识别出来并明确告诉你"什么都没做"）。
本版改了共享配置的结构（`repos:` 段的值下沉到各人那份，**键名留在共享文件里**），
**换机器/新接入**的同事请照 `config/harness.local.example.yaml` 生成自己那份；
已在用的机器 pull 之后无需额外动作 —— 你那份 `local.yaml` 里原先怎么填的照旧生效。

## 卸载（一步）
包内 → `python uninstall.py --harness <你的 agentguard 路径>`（预演）→ 加 `--yes` 执行。
`bootstrap.py` clone 出来的那个仓库**不在**撤回清单里 —— 那是你自己的仓库，去留由你决定。

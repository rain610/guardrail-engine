# agentguard 内部安装包 · v0.1.7-dev（2026-09-23）

> 内部试用版（仅限公司内部使用，请勿外发）。
> 这是**修复档**：外部评审（AutoClaw，2026-09-23）报了 33 项（2 高 / 12 中 / 19 低），**逐条落地**
> —— 该改的改，属业务判断的**明确不改并写明理由**（见下「有意不做的四条」）。
> 最重的一条是**旗标注入**：`run t <文件> --mode loose <坏文件>` 能把一次拦截（rc=1）翻成放行（rc=0），
> 因为三个入口把调用方给的 files **原样拼在 gate 名之后** —— 于是一个内容为 `--mode` 的「文件名」
> 就能让**被检方自己放宽门禁**。现在这类参数一律 **rc=2 fail-closed**。
> 另有若干条是同一个形状：**判据宽了一格，于是它问的问题不是它想问的**
> （R1 只认一条 Controller 前缀、`\boverride\b` 能吃 `overrideEnabled`、`"const" in line` 能吃
> 字符串里的 const、注释里的「代码」被当真代码）。
> **无破坏性变更**，可直接覆盖安装；各人那份 `config/harness.local.yaml` 不用改。
> ⚠ 装过编辑期 hook 的机器：`git pull` 之后**重跑一次** `python <HARNESS>/sandbox/install_shim.py`
> —— 全局守则的哨兵区要重渲染（本版守则正文有变动，见「维护者」小节）。

## 包内容
- `agentguard-0.1.7.dev0-py3-none-any.whl` —— CLI + MCP 薄服务（`pip install` 后得到 `agentguard` 命令）
- `marketplace/` —— Claude Code / OpenClaw 插件市场 bundle（技能 + MCP，一次装齐）
- `bootstrap.py` —— 引擎引导（把门禁引擎仓 clone 到本机，接入的第一步）
- `fix_paths.py` —— 换机器路径适配（一条命令改到你的 python / 引擎路径）
- `upgrade.py` —— 升级入口（按你的布局给出该执行的动作，不猜）
- `uninstall.py` —— 一键卸载（默认预演、`--yes` 执行；逐项撤回，可逆 + 台账留痕）
- `安装说明.md` / `OPENCLAW.md` / `LICENSE` / `SHA1SUMS.txt` / `PACK-INFO.json`

## 本版变化（相对 v0.1.6-dev）

### 同事能直接感觉到的

- **旗标注入已封**（H1，高危）。这条不是理论风险，是**一条能跑通的绕过路径**：
  门禁的三个入口（`cli.py` / MCP / `auto-gate`）都把你给的文件名**原样拼在 gate 名后面**，
  于是「一个叫 `--mode` 的文件」会被当成**开关**读进去，让**被检方自己**把判据放宽。
  现在旗标形态（`-x` / `--x`）的位置参数一律 **rc=2 fail-closed**，错误文案逐字打出是哪一项；
  `--` 之后全归位置参数（要检真叫这个名字的文件，走 `--`）。并**断言拒绝时门禁根本没被跑过**
  —— 否则等于换个口径又判了一次。
  顺带：`--mode` 真被调用方覆盖时，台账记 `mode_override`，并把 **loose 方向**标进 `weakened`
  （把「收紧」也记成 weakened 是说假话）。
- **行内豁免 `harness-ok:` 必须落在注释里**（L4）。此前**字符串里**写的也生效
  —— `console.log("harness-ok: PC-CONSOLE …")` 这种就能把整行豁免掉，而那行代码**照样会跑**。
  如果你之前无意中靠这种写法过的，现在会被拦：**那是修对了**，把标记挪到注释里即可。
- **Trae / Qoder 的示例配置以前是照抄必坏的**（M8/M9）：命令被**双重转义**、里面那个 `_契约` 块
  是**已作废口径**、而且与自家体检器**三向矛盾**。两份 example 已重写。
- **演练的退出码不再骗人**（L15）：`upgrade.py` 不带 `--yes` 时，原先会把它自己刚攒下的失败清单
  **丢掉、一律返回 0** —— 同一份清单在 `--yes` 支判 rc=1、演练支判 rc=0，脚本化调用
  （`if rc==0 then …`）会把「预演里有 ✗」读成「演练通过」。现在两支**同一判据**。
  实测（同一夹具、同一台机器，只换脚本版本）：缺 `marketplace/` 的包 **rc=0 → rc=1**。
- **`.cmd` / `.bat` 不再先经 `cmd /c`**（L14）：那层 shell 会让 cmd **再解析一遍**引号，
  实测**路径与参数都含空格**时 rc=1 且**输出为空**（"看着跑了、其实没有"）。判据不是「碰巧能跑」：
  直接调 `CreateProcessW`（绕开 subprocess）也能跑 `.cmd` ⇒ 是**操作系统本人**认它。
  三份实现现在口径一致。
- **范式库里的本机知识库路径不再出货**（L18）：实测 **7 处 / 5 文件**，且**写法有三种**
  （大写盘符 `D:/…`、git-bash 形 `/d/…`、**裸名字 `KnowledgeVault/…`**）—— 前导既不是盘符也不是
  `/d/`，两种「按形态扫」的正则**都不命中**，所以以前按形态扫的审计**看不见它**。
  6 处活指针已改成 `<VAULT>`；定义留在**你自己那份** `~/.agentguard/GLOBAL_AGENTS.md`（哨兵区外）。
- **后端同事会多看到一类 R1 提示**（L5）：R1 的作用域原先只认 `RMC/Eagle.RMC.Controller` 一条前缀，
  现在按**后缀**判定 `Eagle.<组>.Controller`（实测受管仓真实存在的恰四条：RMC/RMCHY/Module/Support）。
  实测 **+15 文件 / +15 行**。**R1 恒 info ⇒ 只多观察，不改任何拦截裁决**。
  ★ 报告建议的 `*/Eagle.*.Controller` **被否决**：实测它会把 `Eagle.RMCEx.ApiController` 与
  `Eagle.RMC.ApiController` 一并吞进来（`.*` 能吃 `RMCEx.Api`）—— 那是**另一套防腐层**。
  同时 F3/F6 从「只报首个命中行」改为**报全部命中行**：往存量文件里新加第二处，不再被静默漏掉。
- **`keji_v3` 后端线已纳管**（用户 2026-09-23 裁决；`ntrx-class-meeting-video` 是基于 ntrx 的
  **临时功能分支 → 不纳管**）。★ 顺带查清：`D:/MyProject/aiauto/` 下那些目录**都是
  `agentguard_back_net` 一个仓的 git worktree**，共用 `.git` 配置 ⇒ `core.hooksPath` 是**共享**的。
  所以 `keji_v3` **一直有钩子**，只是跑到时按 `rc=3 非受管`跳过 —— 又一处「看着有、其实没在管」。
  实测改后同一条路径 **rc=0**，且 `cli.py check` 在真实 `BaseApiController.cs` 上跑出
  `gate=keji_v3_backend`（**规则真跑**，不只是「认得出仓」）。
- **`docs/新同事接入指南.md`（新增）**：从零接入导览 8 节，每节标出权威源。
- **CodeBuddy 定为「两件套」（`AGENTS.md` + `CLAUDE.md`）**；PC 两仓那份 `RULE.mdc` 是
  **规则正文的第二份副本**（两份 sha256 相同、把维护机绝对路径写死 3 处、其中一处是让 AI 去执行
  一个死路径脚本，且全仓**无生成者、无读取者**）⇒ 已删。README 的 node 那行同时补齐**两档**行为
  （编辑期只 skip / **提交期 fail-closed**）—— 原先只说「skip 而非拦」是半句真话。

## 安装（三步）
1. `python "<本包目录>\bootstrap.py"` —— clone 引擎仓（已 clone 过会直接跳过并说"什么都没做"）
2. `python "<本包目录>\fix_paths.py" --harness "<你的 agentguard 路径>"` —— 路径适配（每次装/升级都要跑）
3. 按 `安装说明.md` 安装（CLI / Claude 插件 / OpenClaw 任选）

## 升级
见 `安装说明.md`「五、升级」—— 路径引用型（`.mcp.json` 指到你 clone 的仓库）**无需处理**，pull 即可；
副本型（按版本目录放的）重跑安装命令，或 `marketplace add <新路径>`。
**已经 clone 过引擎仓的机器不需要跑 `bootstrap.py`**。
本版**没有改配置结构**，你那份 `config/harness.local.yaml` 照旧。
⚠ 唯一要额外跑一次的：装了编辑期 hook 的机器，`git pull` 之后跑一遍
`python "<HARNESS>/sandbox/install_shim.py"`，全局守则的哨兵区才会重渲染（本版守则正文有变动）。

## 卸载（一步）
包内 → `python uninstall.py --harness <你的 agentguard 路径>`（预演）→ 加 `--yes` 执行。
`bootstrap.py` clone 出来的那个仓库**不在**撤回清单里 —— 那是你自己的仓库，去留由你决定。
全局守则**刻意不退**（区外是你自己写的规矩，撤走等于把它一起拿走）。

# ADR-0001：打包五条铁律（壳与引擎的边界）

- 状态：已接受
- 日期：2026-09-14
- 场景：打包路线（分支 `feat/packaging`；配套《打包执行规划》与《打包分支执行清单》）
- 关联评审教训：G1/K1（意图对、接缝错）、K6（汇总口径）、F3/Q③（人的动作）

## 背景

harness 准备以多种「壳」分发：CLI（`agentguard`）、MCP 薄服务、技能包、宿主插件。
壳越多，「第二份逻辑」和「静默失效面」就越多——本项目历史上最高频的缺陷类，正是
「看起来在跑、其实没在数 / 没在拦」（报平安）。

## 决策（五条铁律）

1. **逻辑只一份（引擎），壳只做转发。**
   壳内禁止：重定义引擎符号（`compute_changed_lines` / `_find_hits` / `filter_hits_by_lines` /
   `is_untracked` / `script_line_offset` 等）；禁止行号 / 坐标系运算
   （K1 教训：跨层坐标系是本项目最高频的静默失效点，壳层只用 rc + 摘要）。
2. **每个新壳上线即进 ENTRIES 清单 + doctor 体检。**
   「壳没装好 / 装歪」必须可见（否则又一次「报了平安没人知道」）。
3. **版本单源：** `VERSION` → CLI `--version` → MCP serverInfo → 技能 metadata，四处一致（测试锁定）。
4. **人的动作永不进自动化壳：** accept / 改基线只允许真实终端（F3/Q③ 结论）。
5. **分发不得改变强制层行为：** hooks-dir / install 流程 / 2 个 gate 语义不变。

## 后果

- 新增壳必须进入 `tests/test_packaging_contract.py` 的 `SHELL_FILES` 注册表并通过契约锁；
- 违反铁律 1/5 的改动在评审中直接打回；
- 违反铁律 2/3 的发布视为未完成（M5 验收项）。

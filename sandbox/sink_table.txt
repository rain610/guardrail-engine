# 归宿表 —— 「受管仓里的哪一行可以删，删了以后读者去哪儿找它」
# =====================================================================
# 用途：sandbox/agents_audit.py 的**唯一**判据来源。
#
#   一条行能不能删，只取决于**这一行有没有归宿**，不取决于它属于哪一端。
#   所以「端级模板以后补上归宿」和「全局守则今天就有归宿」走的是同一条路 ——
#   往本文件加一组 [归宿]/[行]，重跑，那一行自动从「待迁」挪进「可删」。
#
# 格式（每组一条归宿，[行] 可重复）：
#   [归宿]   <相对引擎仓根的文件路径>
#   [锚点]   <必须能在那个文件里逐字找到的串 —— 找不到就是「指针指空」，本组作废>
#   [为什么] <一句话：这条归宿是什么>
#   [行]     <受管仓 AGENTS.md 里被它取代的那一行原文>
#
# 两条判据，都刻意选在安全那一侧：
#   ① **归一化后精确相等**，不是子串。比对前把引擎仓绝对路径（正/反斜杠两种写法）
#      抹成 <H> 并折叠空白，否则这套判据只在写表的人那台机器上成立（同事 clone 到
#      D:/dev/ 就整片落进待迁）。差一个标点 → 落到「待迁」= **留而不删**。
#   ② **锚点要能求证到**。改归宿文件的措辞时若忘了同步本表，`--audit`
#      会报「指针指空」，那几行自动退回待迁 —— 不会误删，但也不会静默少删（所以出声）。
#
# ⚠ 删受管仓的知识不可恢复：本表只用于**生成给人过目的
#   diff**。agents_audit.py 没有任何写入路径。

# 退出码语义 —— 三种措辞（行尾 LF / 行尾 CRLF / 分层约束），归宿同一处
[归宿] sandbox/global_agents.py
[锚点] 退出码：0=通过
[为什么] 全局守则正文（退出码语义）
[行] 退出码 0=过 / 1=拦截修复 / 2=配置错。行尾（LF）、写法规范由门禁自动拦，被拦按输出修复，不 `--no-verify`。
[行] 退出码 0=过 / 1=拦截修复 / 2=配置错。行尾（CRLF）、组件写法等**由门禁自动拦**，被拦按输出修复，不 `--no-verify`。
[行] 退出码 0=过 / 1=拦截修复 / 2=配置错。分层约束/编码(utf-8-bom)由门禁自动拦，被拦按输出修复，不 `--no-verify`。
